02 · Research question

What does “ends in 1” mean, formally?

The language is described in words: the set of binary strings whose last symbol is 1. Intuition is not a definition. The question for this project is whether a two-state machine can capture that idea precisely, with no dead state and no third state.

The question, stated

Design a DFA over Σ = {0, 1} that accepts exactly the strings ending in 1. The deliverable is the machine and the visible trace of a run — not the answer alone.

Intuition
“the string finishes with a 1”
Formal target
L = { w ∈ {0,1}* | w|w| = 1 }
Constraint
minimal states, no dead state needed

Why two states might be enough

The machine only needs to remember one thing: whether the last symbol read was a 1. That is one bit of information. Two states can carry one bit — one for “last was 0 (or nothing yet)”, one for “last was 1”.

A dead state is not required here. Both symbols are defined in both states, so every input has a next state. A trap state would only reject strings that should be accepted.

03 · Background & related work

The DFA model, and what it costs

A deterministic finite automaton is the standard model for “regular” languages — those a finite machine can decide by memory alone, with no stack and no counter. The definition is older than the assignment, and it is the same definition the code implements.

The model (standard)

States
a finite set Q
Alphabet
a finite set Σ
Transition
δ : Q × Σ → Q
Start
q0 ∈ Q
Accepting
F ⊆ Q

Why this problem is a good teaching example

  • ✓Minimal machine — two states, easy to draw and to trace by hand.
  • ✓No dead state — every symbol is defined everywhere, so there is no trap to confuse the reader.
  • ✓One bit of memory — the state is the only thing remembered, which is the point of the model.
  • ✓A clear acceptance rule — final state decides, not the last character.

Related approach that fails here. A machine that looks for the substring “101” needs more states and a different language. That is a different question — and out of scope, on purpose.

08 · System design

Why a server instead of file://. WebView2 would cache script.js and styles.css, so after an edit a relaunch can quietly run the previous build. Everything is served no-store.

The bridge is async and returns data, never a verdict the view may re-derive.

09 · The invariant

dfa.py decides.
script.js renders.

# the one rule
All DFA logic lives in dfa.py. script.js renders what Python
returns and must never decide anything.

# corollary
no innerHTML          no insertAdjacentHTML
no string-concatenated markup          user input can contain anything
every value is written with textContent

# consequences
script.js has no transition table, no validate(), no simulate()
script.js contains no hex colour

Two implementations can disagree. There is only one. If the figure, Table 1 and dfa.py ever disagree, dfa.py is right.

12 · Input validation

The machine never saw it

Input · 1021

  1. 11
  2. 22not in Σ
  3. 13

Result · alert

✕ ERROR: Invalid input. The DFA only accepts the symbols 0 and 1.

  • Found “2” at position 3.

Remove the highlighted symbol and check again.

–No result.

An invalid string is never reported as accepted or rejected. Validation runs before the automaton, so the machine never saw this input — there are no steps, no flow, and no final state to report.

The rule

Alphabet
Σ = {0, 1}
Positions
1-based
Whitespace
never trimmed
On error
{ status: "invalid", errors: [{ symbol, index }] }
Rendered
nothing except the message

The same rule covers 10a1, 10 1, 101 , 2 and abc. Eight of the 29 oracle cases are invalid inputs, and none of them reach the automaton.

14 · Reliability

A launch that repairs itself

Rules it follows

  • ·A restore that does not verify is reported as a failure, not a success.
  • ·One restart, then stop at MAX_REPAIRS (8) instead of looping for ever.
  • ·An app that exits inside LAUNCH_GRACE_S (10 s) is retried once.

Honesty about a missing baseline

  • ·If the manifest or backups are gone, the launcher says integrity cannot be checked. It does not claim a guarantee it cannot make.
  • ·--maintenance suspends restoration entirely, including the pre-launch check, so deliberate work is not undone.
